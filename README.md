# STM32 FreeRTOS LED Blinking Lab

Two LED2 blinking procedures on STM32 using CMSIS-RTOS v2 (FreeRTOS), with a semaphore protecting the shared LED. Completes the **Basic Problem** and **Option Problem A**.

### Behavior

LED2 is shared by two independent blinking procedures:

**Task_1: button-triggered blink** (`Press_task`)

Pressing the User Button triggers a blink. The press duration selects which pattern runs:

| Press type | Condition | LED2 |
|---|---|---|
| Short press | Released within 1 s | 1 Hz for 5 s |
| Long press | Held 1 s or longer before release | 10 Hz for 5 s |

The EXTI interrupt notifies `Debounce_task`, which measures the press duration and sends `0` (short) or `1` (long) to `Task_1` through `Queue_press`. A queue is used instead of a binary semaphore so the two press types can be distinguished.

**Task_2: periodic blink** (`Periodical_Task`)

Every 10 s, a software timer releases `Periodical_Sema`, and LED2 blinks at 10 Hz for 2 s.

**Mutual exclusion**

Both tasks acquire `Critical_section_Sema` before blinking and release it when done. If one procedure is running, the other waits for it to finish instead of interfering with LED2. LED2 is turned off at the end of every procedure.

### Hardware and Environment

| Item | Value |
|---|---|
| MCU | STM32L475VGTx |
| RTOS | FreeRTOS (CMSIS-RTOS v2 API) |

| LED2 | GPIOB `LED2_Pin` |
| HAL time base | TIM6 |

### Debouncing

The User Button on this board is worn, so while it is held down the signal can briefly bounce back to high, and a single press sometimes fires several interrupts. Debouncing is handled in a dedicated `Debounce_task` instead of the ISR:

1. The EXTI callback (both edges) only releases `IRQ_Sema`, keeping the ISR short.
2. `Debounce_task` waits 30 ms with `osDelay`, then reads the settled pin level.
3. `stable_level` tracks the last accepted state, so extra wake-ups caused by bouncing are ignored.
4. On release, the press duration decides the message sent to `Queue_press`: `1` for long press (≥ 1 s), `0` for short press.
